# Формат bundle 2

Формат 2 введён в `bundle.py 0.2.0`. Bundle является Markdown-документом. Каждый запуск с `-o`, вывод в stdout или добавление через `-a` создаёт самостоятельный фрагмент.

## Границы фрагмента

```markdown
<!-- bundle:fragment:start -->
<!-- bundle:format=2 -->
<!-- bundle:generator=bundle.py version=0.2.0 -->
...
<!-- bundle:fragment:end -->
```

При `-a` старые фрагменты не пересчитываются. Новый фрагмент получает собственные метаданные и manifest.

## Метаданные

Если не указан `--no-metadata`, поля записываются в стабильном порядке:

```text
Repository: <абсолютный путь корня Git-репозитория или bundle root>
Bundle root: <абсолютный корень, переданный программе>
Branch: <ветка, detached HEAD или not-applicable>
Commit: <полный SHA или not-applicable>
Generated at: <ISO 8601 с timezone>
Git status: clean|dirty|not-a-git-repository
Bundle generator/version: bundle.py <версия>
Included files count: <число файловых записей>
```

При `dirty` следует список `Uncommitted files`. В `Included files count` входят текстовые, бинарные и `path-only`-записи. Каталоги и служебные блоки не входят.

## Идентификаторы записей

Каждая запись содержит машинный блок:

```text
Kind: internal|external
Key: i:<encoded-path>|e:<encoded-path>
Path: "<читаемый путь>"
Repository path: "<путь внутри Git-репозитория>"  # когда применимо
Type: text|binary|path-only|directory
Size: <исходный размер>                            # для содержимого
Restoration: exact|lossy                           # для содержимого
```

`Restoration: exact` означает, что bundle содержит представление, достаточное для побайтового восстановления исходного файла. Это выполняется для бинарных файлов, текстовых файлов без преобразований и текстовых файлов с блоком `Original bytes`.

`Restoration: lossy` означает, что в bundle осталось только нормализованное текстовое представление. Такое состояние возможно после нормализации окончаний строк, удаления BOM, добавления завершающего LF либо применения `--no-binary-backup` к тексту в другой кодировке. SHA-256 в manifest при этом остаётся SHA-256 исходных байтов. Правила извлечения такого содержимого определяются issue №4 и не входят в реализацию создания bundle.

## Пути

Внутренние пути относительны `Bundle root`.

Внешний файл на том же диске хранит путь относительно `Bundle root`, например:

```text
Path: "../trash/file.txt"
Key: e:../trash/file.txt
```

Для внешнего файла на другом диске Windows используется переносимое пространство имён:

```text
Path: "@drive/C/temp/file.txt"
Key: e:@drive/C/temp/file.txt
```

Для UNC-пути используется:

```text
Path: "@unc/server/share/dir/file.txt"
Key: e:@unc/server/share/dir/file.txt
```

Исходный абсолютный путь ОС не сохраняется. Пространства `@drive` и `@unc` обозначают только идентичность внешней записи и не являются неявным путём назначения при извлечении.

`Key` начинается с `i:` или `e:`. Небезопасные символы и Unicode кодируются percent-encoding. Реальные имена `__external__`, `__parent__`, `i:`, `e:`, `%` и `:` не конфликтуют со служебным форматом.

## Текстовые блоки Markdown

Содержимое текстового файла не экранируется и остаётся читаемым. Длина внешнего Markdown-fence выбирается динамически: она всегда больше максимальной последовательности обратных апострофов внутри содержимого.

Например, файл с блоком из трёх обратных апострофов помещается во внешний блок из четырёх или более обратных апострофов. Благодаря этому Markdown-файлы могут содержать собственные fenced code blocks без нарушения границ записи.

Тот же алгоритм применяется к служебным fenced-блокам. Содержимое при выборе fence не изменяется.

## Manifest

Если не указан `--no-manifest`, фрагмент завершается разделом:

```text
<sha256>  <entry-key>
```

SHA-256 вычисляется по исходным байтам до декодирования, нормализации строк и Base64. Текст, Base64 и checksum строятся из одного чтения файла. В manifest входят только текстовые и бинарные файлы. Каталоги, `path-only` и служебные блоки не входят.

## Пустой bundle

Нулевой набор файлов допустим. Команда завершается с кодом `0`, метаданные содержат `Included files count: 0`, а manifest остаётся пустым.

## Внешние файлы и извлечение

Формат помечает внешний файл как `Kind: external`. Автоматическое извлечение внешних файлов запрещено проектным решением. В будущей реализации каждый такой файл должен выбираться отдельно и получать явно заданный путь назначения. Безопасное извлечение и обработка `Restoration: lossy` отслеживаются в issue №4.

## Совместимость

Формат 2 не использует старые искусственные пути `__external__/__parent__/...`. Для минимального вывода доступны совместно `--no-metadata --no-manifest`, но обязательные маркеры версии, границ фрагмента и машинные блоки записей сохраняются.
